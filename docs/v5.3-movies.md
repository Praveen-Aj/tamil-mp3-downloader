# V5.3 — Movie Discovery and Movie Library Documentation

## 1. Scope and Overview
V5.3 introduces Movie Discovery and the Movie Library subsystem for the Tamil MP3 Downloader desktop application.

### Key Objectives Delivered:
- **Movie Data Model & M:N Schema Preservation**: Utilizes the existing V5.1 `movies` and `song_movies` junction table. Canonical songs remain completely independent of movies (`songs.movie_id` was NOT added). Deleting a movie only removes the relationship metadata in `song_movies` and never cascades to delete canonical songs, sources, downloaded files, or download history.
- **Movie Discovery & Source Population**: Bridges metadata discovery with canonical database ingestion. Discovered movie songs resolve into canonical `LibrarySong` records, register their `SongSource` entries, and form `song_movies` links without duplicating canonical songs or files.
- **Movies Library GUI (`MoviesView`)**: A modern dark-themed movie browser featuring debounced search, sort controls, movie cards with badge metrics (total songs, downloaded vs. missing indicators), responsive grid layout, result counters, and database-level pagination.
- **Movie Detail Experience (`MovieDetailView`)**: Comprehensive view of a selected movie showing metadata banner, live metric chips (Total Songs, ✓ Downloaded, Missing), tracklist table, and one-click actions:
  - **`Download All`**: Enqueues all missing songs for the movie through the canonical `DownloadPlanner` / `DownloadJobManager` pipeline.
  - **`Download Missing`**: Verifies authoritative filesystem state, filters out songs whose physical files exist on disk, and enqueues only physically missing tracks without redownloading or duplicating existing files.
- **Accurate Physical Download State**: Uses authoritative filesystem checks (`downloads/` directory inspection and `reconcile_filesystem_integrity()`) rather than naive in-memory flags.
- **User-Facing Terminology**: Strictly presents user-centric terms (`✓ Downloaded`, `Not Downloaded`), avoiding internal architectural jargon (`OWNED`, `UNOWNED`, `FTS5`, `hash`).

## 2. Architecture & Data Flow

```
                      +-----------------------------+
                      |       Movie Discovery       |
                      | (Sources / Providers / API) |
                      +--------------+--------------+
                                     |
                                     v
                      +-----------------------------+
                      |   LibraryService / SQLite   |
                      |   (Canonical Deduplication) |
                      +--------------+--------------+
                                     |
              +----------------------+----------------------+
              |                                             |
              v                                             v
     +-----------------+                           +-----------------+
     |     movies      | <====== song_movies =====> |      songs      |
     | (id, title,...) |          (M:N)            | (canonical id)  |
     +-----------------+                           +--------+--------+
                                                            |
                                                            v
                                                   +-----------------+
                                                   |  song_sources   |
                                                   +--------+--------+
                                                            |
                                                            v
                                                   +-----------------+
                                                   | DownloadPlanner |
                                                   +--------+--------+
                                                            |
                                                            v
                                                   +-------------------+
                                                   |DownloadJobManager |
                                                   +--------+----------+
                                                            |
                                                            v
                                                   +-------------------+
                                                   | Filesystem / Disk |
                                                   |   (downloads/)    |
                                                   +-------------------+
```

### Movie ↔ Song Relationship Rules:
1. A movie contains multiple songs (`movie_id -> song_id`).
2. A song can belong to multiple movies (`song_id -> movie_id_1, movie_id_2`), such as compilations, reprises, or cross-releases.
3. Canonical song identity (`songs.id`, `title_normalized`, `artist`) is completely decoupled from movie identity.
4. Foreign key integrity: `FOREIGN KEY (movie_id) REFERENCES movies(id) ON DELETE CASCADE` and `FOREIGN KEY (song_id) REFERENCES songs(id) ON DELETE CASCADE`.
5. Deleting a movie only removes records from `song_movies`. The canonical songs, sources, and local mp3 files in `downloads/` remain untouched.

## 3. Database & Repository Enhancements (`library/database.py`)

No new migrations or breaking schema modifications were needed because V5.1 Migration 4 established `movies` and `song_movies`. Clean repository methods were added to `SQLiteDatabase`:

1. `update_movie(movie_id, title=None, year=None, director=None, music_director=None, banner_url=None)`: Thread-safe movie record updates.
2. `search_and_filter_movies(query='', sort_by='title', sort_dir='asc', limit=20, offset=0)`:
   - Performs SQL-level filtering and pagination (`LIMIT ? OFFSET ?`).
   - Uses SQL aggregation with `LEFT JOIN song_movies` and `LEFT JOIN songs` to calculate `song_count` and `downloaded_count` within a single query, preventing N+1 performance bottlenecks.
3. `get_movie_download_stats(movie_id)`:
   - Returns `{ 'total_songs': int, 'downloaded_songs': int, 'missing_songs': int }`.
   - Cross-verifies physical file presence on disk (`file_path` verification and `downloads/` inspection) so deleted physical files are properly marked as missing.
4. `get_movie_songs_detailed(movie_id)`:
   - Retrieves all songs linked to a movie with full canonical metadata, primary source information, and verified download state.
5. `reconcile_filesystem_integrity()` enhancement:
   - Automatically resets orphaned `DOWNLOADING` or `QUEUED` records in `downloads` and `songs` to `NEW` if interrupted by an application restart or crash, ensuring stale queue locks never block subsequent downloads.

## 4. Service Layer (`ui/services/library_service.py`)

The `LibraryService` bridges the database, discovery sources, and the download pipeline:

- `get_movies_page(query, sort_by, sort_dir, page, page_size)`: Computes 1-based page offsets, returning `(movies, total_count, total_pages)`.
- `get_movie_details(movie_id)`: Retrieves the movie metadata, song list, and physical download stats.
- `plan_movie_download_all(movie_id)`:
  - Fetches all canonical songs for the movie.
  - Queries `DownloadPlanner.plan_download()` for each song.
  - Skips songs that are already `OWNED` / downloaded.
  - Returns `(queued_jobs, skipped_count, plan_summary)`.
- `plan_movie_download_missing(movie_id)`:
  - Queries authoritative download states.
  - Filters strictly for missing songs whose physical files do not exist or where high-quality upgrades are eligible.
  - Submits valid jobs to `DownloadJobManager`.
- `discover_movies_from_sources()`:
  - Scans existing registered canonical songs and sources.
  - Extracts album/movie metadata and links them into `movies` and `song_movies` idempotently, preventing duplicate canonical songs and duplicate relations.

## 6. Download UX & Pipeline Integration

- **No Second Download Engine**: Movie downloads route directly through the existing `DownloadPlanner` and `DownloadJobManager`.
- **Download Registry Backwards Compatibility**: Maintained compatibility with `DownloadRegistry.acquire(song_id, song_source_id)`.
- **Non-Blocking Execution**: Jobs run asynchronously via worker threads; the Tkinter main loop remains responsive.
- **Reconciliation & Idempotence**:
  - Calling `Download Missing` repeatedly detects that physical files exist in `downloads/` and queues 0 jobs, preventing duplicate files or redundant network calls.
  - Quality upgrades from lower bitrates (e.g., 128 kbps to 320 kbps) are handled per existing `DownloadPlanner` rules without downgrading.

## 8. Known Limitations
1. **Live External Scraper Provider for Movies**: As established in V5.0 provider architecture, external websites frequently rotate DOM structures. Movie discovery currently synchronizes and groups canonical library sources and album metadata into movies. Real-time external movie scrapers will be expanded in future provider plug-ins.
2. **Artwork Images**: Movie banners and album art rely on local placeholder art or remote URLs when present in source metadata. A dedicated local artwork caching/resizing pipeline is planned for V5.7.
