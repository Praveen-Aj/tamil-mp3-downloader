# V5.2 — Search & Filtering Documentation

## 1. Scope
V5.2 implements an efficient, scalable, and responsive Search & Filtering subsystem for the Tamil MP3 Downloader desktop application.

### Key Objectives Delivered:
- **Canonical Database Search**: Local SQLite full-text search without redundant web scrapes or external API overhead during library navigation.
- **SQLite FTS5 Full-Text Index**: Virtual table `songs_fts` using unicode tokenizer (`unicode61 remove_diacritics 2`) with real-time synchronization triggers (`songs_ai`, `songs_ad`, `songs_au`) and backfill.
- **Composable Filtering**: Composable filtering by Download Status (`ALL`, `DOWNLOADED`, `NOT DOWNLOADED`), Audio Quality (`320 kbps`, `128 kbps`), Source/Provider (`MassTamilan`, `Tamilmp3`, `FriendsTamilMP3`), and Artist.
- **Multi-Column Sorting**: SQL-level sorting on `id` (Recently Added), `title` (Title A-Z), `artist`, `album`, `quality` (Bitrate), `state` (Status), and `year`, with toggleable sort direction (↑ / ↓).
- **Scalable Pagination**: Multi-page SQL slicing using `LIMIT ? OFFSET ?` and `COUNT(*)` without loading full database tables into GUI memory.
- **Enhanced Music Library GUI**: Modern dark-themed UI featuring 250ms debounced search, instant clear button (`✕`), filter dropdowns, dynamic result counts (`Found X matching songs`), table header column sort callbacks, and a friendly empty state ("No songs found", "Try adjusting your search keywords or clearing active filters.", `[Reset All Filters]`).

## 3. Database Changes & Migration 5
Migration 5 was added to `library/migrator.py`, bumping `CURRENT_VERSION` to 5.

### Schema Additions:
```sql
-- Virtual Table using FTS5 with unicode61 tokenizer
CREATE VIRTUAL TABLE IF NOT EXISTS songs_fts USING fts5(
    title,
    artist,
    album,
    content='songs',
    content_rowid='id',
    tokenize='unicode61 remove_diacritics 2'
);

-- Triggers to synchronize songs_fts with songs table
CREATE TRIGGER IF NOT EXISTS songs_ai AFTER INSERT ON songs BEGIN
    INSERT INTO songs_fts(rowid, title, artist, album)
    VALUES (new.id, new.title, coalesce(new.artist, ''), coalesce(new.album, ''));
END;

CREATE TRIGGER IF NOT EXISTS songs_ad AFTER DELETE ON songs BEGIN
    INSERT INTO songs_fts(songs_fts, rowid, title, artist, album)
    VALUES ('delete', old.id, old.title, coalesce(old.artist, ''), coalesce(old.album, ''));
END;

CREATE TRIGGER IF NOT EXISTS songs_au AFTER UPDATE ON songs BEGIN
    INSERT INTO songs_fts(songs_fts, rowid, title, artist, album)
    VALUES ('delete', old.id, old.title, coalesce(old.artist, ''), coalesce(old.album, ''));
    INSERT INTO songs_fts(rowid, title, artist, album)
    VALUES (new.id, new.title, coalesce(new.artist, ''), coalesce(new.album, ''));
END;

-- Performance indexes for composable filtering & sorting
CREATE INDEX IF NOT EXISTS idx_songs_quality ON songs(quality_kbps);
CREATE INDEX IF NOT EXISTS idx_songs_title ON songs(title_normalized);
CREATE INDEX IF NOT EXISTS idx_songs_year ON songs(year);

-- Rebuild full text index from existing songs
INSERT INTO songs_fts(songs_fts) VALUES('rebuild');
```

Migration execution was enhanced to use `self.db._conn.executescript(migration_sql)` to ensure multi-statement trigger bodies with embedded semicolons execute without syntax fragmentation.

## 4. Search Implementation
The search feature is mediated through `library/filter_engine.py`:
- User queries are parsed and tokenized safely using `re.findall(r'[\w]+', query, re.UNICODE)`.
- Each token is transformed into an FTS5 prefix match token (`"token"*`), allowing fast partial matching (e.g. `vaathi` matches `Vaathi Coming` and `Vaathi Raid`).
- Unicode and Tamil scripts (e.g. `வாத்தி கமிங்`, `அனிருத்`) are fully supported by `unicode61`.
- Special search operators and punctuation (`"`, `*`, `:`, `(`, `)`) are sanitized so they cannot cause SQLite syntax errors.
- Graceful fallback: If an FTS query encounters any operational error, `SQLiteDatabase.search_and_filter_songs` falls back automatically to parameterized `LIKE` pattern matching.

## 5. FTS Implementation & Synchronization
- **Virtual Table**: `songs_fts` acts as an external content table pointing to `songs(id)` (`content='songs', content_rowid='id'`). Canonical song data is not duplicated.
- **Triggers**:
  - `songs_ai`: Automatically inserts newly registered songs into `songs_fts`.
  - `songs_au`: Updates title, artist, and album in `songs_fts` on song edits.
  - `songs_ad`: Deletes song references from `songs_fts` on song removal.
- **Backfill**: Existing records from pre-V5.2 databases are indexed immediately during Migration 5 via `INSERT INTO songs_fts(songs_fts) VALUES('rebuild')`.

## 6. Composable Filters
Filters are defined in `SongFilterCriteria` and generated by `ComposableFilterEngine`:
- **Download Status**:
  - `ALL`: No state restriction.
  - `DOWNLOADED`: Only songs in `OWNED` state (verified by physical presence on disk).
  - `NOT DOWNLOADED`: Only songs in `NEW` state.
  *(Internal terms `OWNED` / `UNOWNED` are strictly isolated from user-facing UI).*
- **Bitrate / Quality**: Filters songs meeting minimum bitrate threshold (`320 kbps`, `128 kbps`).
- **Source / Provider**: Filters songs having registered variants from a specific provider (`masstamilan`, `tamilmp3`, `friendstamilmp3`).
- **Artist**: Filters songs by normalized artist name.
- **Composition**: All filter conditions compose with `AND` clauses in SQL, allowing combinations such as:
  `Search: "Anirudh" + Status: DOWNLOADED + Quality: 320 kbps`.

## 7. Sorting
- Supported sort fields: `Recently Added` (`s.id`), `Title` (`s.title_normalized`), `Artist` (`s.artist_normalized`), `Album` (`s.album_normalized`), `Bitrate` (`s.quality_kbps`), `Status` (`s.state`), `Year` (`s.year`), and `Relevance Rank` (`songs_fts.rank`).
- Toggleable direction: Ascending (`ASC`, `↑`) and Descending (`DESC`, `↓`).
- Table header columns in `SongTable` are interactive; clicking column headings updates sorting and toggles direction.

---

## 8. Pagination
- Pagination is performed at the SQL query level using `LIMIT ? OFFSET ?`.
- Result counts use `SELECT COUNT(*) ...` across active joins, avoiding full-table memory loading.
- Controls include `« First`, `‹ Prev`, `Next ›`, `Last »`, and dynamic status `Page X of Y (N songs)`. Buttons are disabled when at page boundaries.

## 14. Known Limitations
- The artist dropdown in the filter bar is capped to 50 distinct items to prevent UI popup lag on large catalogs. Full artist filtering remains accessible via the search bar.
- FTS5 ranking is used as primary relevance order when a text search query is present and no explicit column sort is requested.

## 15. Deliberately Deferred to V5.3+
The following features are strictly out of scope for V5.2 and deliberately deferred to future V5 phases:
- Movies discography view and movie poster browsing (V5.3).
- Artist detail pages with composer/singer/lyricist breakdowns (V5.3).
- Playlists UI creation, custom playlist reordering, and chart exploration (V5.4).
- Artwork cache management and offline album thumbnail embedding (V5.5).
