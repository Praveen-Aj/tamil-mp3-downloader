# V5.4 — People & Music Credits Documentation (Artists, Singers, Music Directors & Actors)

## 1. Scope and Overview
V5.4 introduces the People / Music Credits subsystem for the Tamil MP3 Downloader application. It empowers users to discover, search, filter, and browse individuals across three major creative roles in Tamil cinema:
1. **Singers / Artists** (Vocalists and track performers)
2. **Music Directors / Composers** (Score and soundtrack creators)
3. **Actors** (Cast members associated with films and soundtracks)

### Key Objectives Delivered:
- **Unified Canonical Identity**: Leverages the existing V5.1 `artists` entity alongside existing relational junction tables (`song_artists`, `movie_composers`, `movie_actors`) without introducing redundant tables or schema alterations.
- **Dynamic Multi-Role Derivation**: Individuals can simultaneously be Composers, Singers, and Actors (e.g., Hiphop Tamizha, Vijay Antony, Silambarasan TR, Dhanush). Multi-role classifications are derived dynamically from database relationships rather than being statically constrained to a single column.
- **Canonical String Normalization**: Discovers and merges person variations (e.g., "SPB" / "S. P. Balasubrahmanyam", "A. R. Rahman" / "AR Rahman", case variations, Tamil Unicode) into canonical identities via `normalize_string()`.
- **Composite Artist Splitting**: Intelligent parser (`split_artist_names`) that splits multi-artist credits containing `feat.`, `ft.`, `&`, `,`, `/`, `with`, `vs.` while preserving name integrity.
- **Artists Library GUI (`ArtistsView`)**: Dark-themed browse view featuring role filter tabs (`All`, `Singers`, `Music Directors`, `Actors`), debounced search, responsive 3-column card grid with role badges and track counts, and pagination.
- **Artist Detail Experience (`ArtistDetailView`)**: Comprehensive person profile with metadata hero header, role badges, verified metrics chips (Songs, Movies, Downloaded, Missing), dual-tab interface (`Songs` and `Movies`), and one-click download controls:
  - **`Download Missing`**: Authoritatively checks physical files on disk and queues only missing tracks via `DownloadPlanner` and `DownloadJobManager`.
  - **`Download All`**: Enqueues all songs associated with the artist.
- **Bidirectional Navigation**: Fluid jumping between Movies and Artists (clicking actor/composer chips on `MovieDetailView` opens their person detail; clicking songs/movies in `ArtistDetailView` navigates to corresponding movies and tracks).
- **Physical Download Integrity**: Verifies valid ID3 headers, audio frame sync bits (`0xFFFB`), and avoids redownloading existing files.
- **Zero Regressions**: Passes all 244 regression test suites (V5.1 migrations, V5.2 search/filtering, V5.3 movie library, V5.4 artists).

### Relational Integrity & Multi-Role Rules:
1. Canonical person identities live in the `artists` table (`id`, `name`, `normalized_name`, `role`, `image_url`).
2. A person's creative roles are computed on demand:
   - **Singer**: Has rows in `song_artists` OR has explicit role `singer` / `vocalist`.
   - **Music Director**: Has rows in `movie_composers` OR has explicit role `composer` / `music_director`.
   - **Actor**: Has rows in `movie_actors` OR has explicit role `actor` / `actress`.
3. If an individual has entries across multiple junction tables, they dynamically earn multiple badges (e.g. `['music_director', 'singer', 'actor']`).
4. Deleting or unlinking an artist from a song or movie never cascades to delete canonical audio files, download history, or other role associations.

## 3. Database Layer Enhancements (`library/database.py`)

All queries use parameterized SQL with efficient aggregation and subqueries to eliminate N+1 overhead:

1. **Artist CRUD & Lookup**:
   - `add_artist(name, role, image_url, normalized_name)`
   - `get_artist(artist_id)`
   - `get_artist_by_name(name)`
   - `get_artist_by_normalized_name(normalized_name)`
   - `update_artist(artist_id, ...)`
   - `delete_artist(artist_id)`

2. **Role & Aggregation Queries**:
   - `get_artist_roles(artist_id)`: Inspects `song_artists`, `movie_composers`, `movie_actors`, and `artists.role` to return a list of active role identifiers.
   - `search_and_filter_artists(query, role_filter, sort_by, sort_dir, limit, offset)`: Uses SQL subquery aggregation with correlated counts for `song_count` and `movie_count`, filtering by role using `EXISTS` clauses on the respective junction tables.
   - `get_artist_statistics(artist_id)`: Returns `{ 'total_songs': int, 'downloaded_songs': int, 'missing_songs': int, 'movie_count': int }`, cross-referenced with disk file existence.
   - `get_artist_songs_detailed(artist_id)`: Fetches all songs linked via `song_artists` with download statuses, file paths, and primary sources.
   - `get_artist_movies_detailed(artist_id)`: Fetches all movies where the person is a composer or actor, annotating their role (`composer`, `actor`, or `both`) and track count.

3. **Flexible Junction Inserters**:
   - `add_movie_actor()`, `add_movie_composer()`, `add_song_artist()`, and `add_song_movie()` were updated to accept either dataclass models or raw positional/keyword arguments (`movie_id`, `artist_id`, `role`).

## 4. Service Layer Enhancements (`ui/services/library_service.py`)

1. **Composite Delimiter Parsing (`split_artist_names`)**:
   - Splits composite credit strings: `"Anirudh Ravichander, Jonita Gandhi feat. Kamal Haasan"`.
   - Recognizes separators: `feat.`, `feat`, `ft.`, `ft`, `&`, `and`, `/`, `,`, `with`, `vs.`, `vs`.
   - Preserves honorifics and initials (`K. S. Chithra`, `S. P. Balasubrahmanyam`).

2. **Library Ingestion & Automatic Enrichment**:
   - `enrich_people_from_library()`: Iterates existing movies and songs, resolves composers, actors, and track artists into canonical `artists` records, and populates `song_artists`, `movie_composers`, and `movie_actors`.
   - `discover_movies_from_sources()`: Automatically extracts composer and singer credits into canonical entities during source discovery.

3. **Download Planning**:
   - `plan_artist_download_all(artist_id)`: Plans downloads for all canonical songs linked to the artist via `DownloadPlanner`.
   - `plan_artist_download_missing(artist_id)`: Evaluates physical disk presence and enqueues only tracks missing from disk.

## 5. User Interface & Workflow

### 1. `ArtistsView` (`ui/views/artists_view.py`)
- **Navigation Sidebar**: Direct link under the `LIBRARY` section with artist icon.
- **Role Filters**: Filter tabs for `All`, `Singers`, `Music Directors`, and `Actors`.
- **Search Bar**: Debounced text search matching artist name or normalized name.
- **Card Grid**: Responsive 3-column grid displaying avatar icon, artist name, role badges (e.g. `Composer`, `Singer`, `Actor`), and track/movie counts.
- **Pagination**: First/Prev/Next/Last pagination controls with total count indicators.

### 2. `ArtistDetailView` (`ui/views/artist_detail_view.py`)
- **Hero Header**: Large avatar, artist name, role pills, and download action buttons.
- **Metric Chips**: Verified pills showing `Songs`, `Movies`, `✓ Downloaded`, and `Missing`.
- **Dual Tabs**:
  - **Songs Tab**: Tracklist with title, movie, duration, source status, and download buttons.
  - **Movies Tab**: Grid of associated movies with year, role annotation (`Composer` / `Actor`), and song counts.
- **Bidirectional Links**: Clicking a movie opens `MovieDetailView`.

### 3. `MovieDetailView` Updates (`ui/views/movie_detail_view.py`)
- Composer and Actor metadata chips are interactive buttons.
- Clicking any composer or actor chip directly navigates to their `ArtistDetailView`.
